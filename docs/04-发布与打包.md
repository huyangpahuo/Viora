# 04 · 发布与打包

> 覆盖:dotnet publish 产出便携包(x64/x86)、Visual Studio 图形化打包、MSIX/.msixbundle、上架微软商店。

## 1. dotnet publish(命令行,推荐)

### 1.1 自包含包(推荐给用户:解压即用,免装运行时)

```bash
# 64 位
dotnet publish src/Viora.App -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=false -o artifacts/viora-1.0.0-win-x64

# 32 位
dotnet publish src/Viora.App -c Release -r win-x86 --self-contained true `
  -o artifacts/viora-1.0.0-win-x86
```

压缩成 zip(Git Bash 里):

```bash
cd artifacts
powershell -Command "Compress-Archive -Path viora-1.0.0-win-x64 -DestinationPath Viora-1.0.0-win-x64.zip -Force"
powershell -Command "Compress-Archive -Path viora-1.0.0-win-x86 -DestinationPath Viora-1.0.0-win-x86.zip -Force"
```

> `-p:PublishSingleFile=true` 也可生成单 exe,但 WPF + 插件宿主建议保持目录形态(插件加载与 `languages/` 外置包都依赖 exe 旁目录)。

### 1.2 依赖框架包(体积小,要求用户装有 .NET 8 Desktop Runtime)

```bash
dotnet publish src/Viora.App -c Release -r win-x64 --self-contained false `
  -o artifacts/viora-1.0.0-win-x64-fr
```

发布前设置版本号:`src/Viora.App/Viora.App.csproj` 的 `<Version>` / `<AssemblyVersion>`(当前 1.0.0;**检查更新按此版本与 GitHub Release tag 比较**)。

### 1.3 单文件发布(v1.0.0 采用的形态)

解压后根目录只有 `Viora.exe + languages\`,找 exe 一目了然:

```bash
# 64 位
dotnet publish src/Viora.App -c Release -r win-x64 --self-contained true ^
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=none ^
  -o artifacts/viora-1.0.0-win-x64

# 32 位
dotnet publish src/Viora.App -c Release -r win-x86 --self-contained true ^
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=none ^
  -o artifacts/viora-1.0.0-win-x86
```

参数说明:

- `PublishSingleFile=true`:运行时与应用 DLL 全部并入一个 exe;
- `IncludeNativeLibrariesForSelfExtract=true`:原生库(如 WPF 渲染 DLL)也打进 exe,首次启动自解压到 %TEMP%(慢 1–2 秒,之后正常);
- `DebugType=none`:不生成 .pdb,包更干净;
- csproj 里的 `<SatelliteResourceLanguages>en;zh-Hans</SatelliteResourceLanguages>` 负责裁掉 cs/de/es 等系统语言文件夹(它们是 .NET 运行时异常消息翻译,与界面语言无关)。

权衡:单文件 exe 个别杀软误报率略高、首次启动稍慢;若需退回目录形态(1.1 节),去掉这三个 `-p:` 参数重发即可。

压缩(Git Bash):

```bash
cd artifacts
powershell -Command "Compress-Archive -Path viora-1.0.0-win-x64 -DestinationPath Viora-1.0.0-win-x64.zip -Force"
powershell -Command "Compress-Archive -Path viora-1.0.0-win-x86 -DestinationPath Viora-1.0.0-win-x86.zip -Force"
```

### 1.4 发布检查清单

- [ ] 版本号已递增(`Viora.App.csproj`);
- [ ] 双语语言包键完整(对照 `_template.json` 键数);
- [ ] Release 构建通过、手工冒烟(安装/卸载插件、风格化、导出、设置各项);
- [ ] GitHub Release:打 tag(如 `v1.0.1`)+ 更新说明 + 附上 zip —— **发布后客户端"检查更新"即可对比到新版本**;
- [ ] `Viora-plugins` 若有插件更新同步发布。

## 2. Visual Studio 图形化打包

1. 解决方案资源管理器 → 右键 **Viora.App** → **发布**(Publish);
2. 目标选 **文件夹**,下一步选 **文件夹**,完成;
3. 发布配置里:**目标框架** net8.0-windows;**部署模式** = 自包含;**目标运行时** = win-x64(再建一个配置选 win-x86 出 32 位版);**文件发布选项**可勾选"生成单个文件"(不推荐,见上);
4. 点击"发布",输出目录即完整可运行目录;
5. 需要两种架构就分别切换"目标运行时"再各发布一次。

> 也可以在 VS 里直接用命令行窗口执行第 1 节的 CLI 命令,效果一致且可脚本化。

## 3. MSIX / .msixbundle(高级安装包)

MSIX 提供干净安装/卸载、完整性校验和商店上架格式。

### 3.1 生成签名证书(本地测试)

```powershell
New-SelfSignedCertificate -Type Custom -Subject "CN=Viora, E=you@example.com" `
  -KeyUsage DigitalSignature -FriendlyName "Viora" `
  -CertStoreLocation "Cert:\CurrentUser\My" `
  -TextExtension @("2.5.29.37={text}1.3.6.1.5.5.7.3.3", "2.5.29.19={text}")
# 导出 .pfx(把上面指纹替换进去)
$pwd = ConvertTo-SecureString -String "你的密码" -Force -AsPlainText
Export-PfxCertificate -Cert "Cert:\CurrentUser\My\<指纹>" -FilePath .\Viora.pfx -Password $pwd
```

### 3.2 方式一:Windows Application Packaging Project(图形化)

1. 解决方案 → 添加 → 新建项目 → **Windows Application Packaging Project**(需安装"通用 Windows 平台开发"工作负载);
2. 该打包项目添加**应用程序引用** → 勾选 `Viora.App`;
3. 双击生成的 `Package.appxmanifest`:显示名、版本号、**包标识名称/Publisher**(与签名证书 subject 一致,如 `CN=Viora`);
4. 右键打包项目 → **商店** → **创建应用程序包**:
   - 选"I want to create packages for sideloading"(本地)或"For the Microsoft Store"(上架);
   - 架构勾选 x64 与 x86 → 生成 `.msix` / `.msixbundle`;
   - 选择签名证书(测试用自签名;商店上传会被微软重新签名)。
5. 安装测试:双击 `.msix`(需先信任证书:证书文件 → 右键安装到"本地计算机 → 受信任的人")。

### 3.3 方式二:命令行打 MSIX(把现有 publish 输出装进包)

```powershell
# 安装工具
dotnet tool install --global dotnet-mspack   # 或使用 makeappx(Windows SDK 自带)
# 打包(目录 → .msix)
MakeAppx pack /d artifacts\viora-1.0.0-win-x64 /p Viora.msix /o
# 签名
SignTool sign /fd SHA256 /a /f Viora.pfx /p 你的密码 Viora.msix
# 合并 x64+x86 为 bundle
MakeAppx bundle /bv 1.0.0.0 /d .\bundles /p Viora_1.0.0.msixbundle /o
```

> MSIX 包内需要 `AppxManifest.xml`;用打包项目(3.2)会自动生成,纯命令行则建议以 3.2 为主、3.3 用于 CI。

## 4. 上架微软商店

1. [Microsoft Partner Center](https://partner.microsoft.com/) 注册开发者个人账号(一次性约 $19);
2. Partner Center → 应用 → 新建应用 → 保留名称(如 `Viora`);
3. 首次提交需要填写:描述、截图(可直接用 `docs/images/` 四张)、分类、隐私政策 URL(必须,哪怕是一页静态说明)、网站(可选);
4. 包上传:提交 **MSIX / .msixbundle**(经 3.2 用"For the Microsoft Store"生成,或 3.3 签名后上传);微软会自动重签;
5. 分级问卷(IARC)、按向导走完 → 提交审核(通常 1–3 天);
6. 通过后用户即可在商店搜索安装,自动更新由商店接管;
7. 注意:商店版与 GitHub 版并存时,**检查更新**功能建议在商店渠道下关闭或提示"由商店更新"(可按安装来源判断,后续版本处理)。

## 5. 常见问题

| 问题 | 处理 |
|---|---|
| 用户机器报缺 `WebView2`/运行时 | 本应用为自包含发布,无需任何运行时;若用依赖框架发布,请引导安装 .NET 8 Desktop Runtime |
| MSIX 安装报证书不受信任 | 测试机先安装并信任 .pfx(本地计算机 → 受信任的人) |
| 商店审核被拒:隐私政策缺失 | 准备一个静态页说明"完全本地处理,不收集数据"即可 |
| x86 包有意义吗 | 仅照顾极老旧 32 位系统;主流用户发 x64 即可 |
