# 06 · 插件工坊扩展:开发与发布指南

> **定位**:插件工坊不再做独立桌面程序,改为 **VS Code 扩展**。插件本来就是磁盘上的 C# 文件夹工程,VS Code + C# 扩展已经把"编辑代码"做到最好;工坊扩展只补工程化的一段——**脚手架、校验、打包、装进 Viora 测试**。
> 本文档面向**亲手做扩展的你**:从零创建、本地调试、打包 .vsix、上架 VS Code Marketplace,全程一条线走通。具体功能实现交给 AI 时,直接把 §5 的任务书贴给它,并让它读 [AGENT.md](../AGENT.md)。

## 0. 工坊扩展做什么、不做什么

**做**:
- 「新建风格插件」脚手架:按 [插件开发指南](03-插件开发指南.md) 的结构生成 csproj + 入口 + 算法示例 + `plugin.json`;
- `plugin.json` 校验(JSON Schema + 插件 ID 规则诊断);
- 「打包」:`dotnet build` → DLL + 清单压成 `dist\<id>.zip` → 生成 `registry.json` 条目;
- 「安装到本地 Viora」:把 zip 解压进 Viora 的 `plugins\` 文件夹,立刻在应用里试效果。

**不做**:实时效果预览(渲染依赖 Viora 的 WIC 管线,作者装进 Viora 看效果即可;将来若做,用 .NET 预览 CLI 出图再由扩展展示,属二期)。

## 1. 准备环境

1. **Node.js LTS**(20 或 22,https://nodejs.org 下载安装)——`node -v`、`npm -v` 能出版本号即可;
2. **VS Code**(你已经在用了);
3. 发布时才需要:`npm install -g @vscode/vsce`(打包/发布 CLI),可选 `npm install -g ovsx`(发布到 Open VSX)。

## 2. 创建扩展项目

### 2.1 用官方脚手架(推荐)

```bash
npm install -g yo generator-code
mkdir vscode-workshop && cd vscode-workshop
yo code
```

问卷怎么选:

| 问题 | 选择 |
|---|---|
| What type of extension? | **New Extension (TypeScript)** |
| Extension name | `viora-workshop` |
| Description | `Viora style-plugin workshop: scaffold, validate, pack, install` |
| Bundle the source with esbuild? | **Yes**(产物小、启动快) |
| Which package manager? | npm |
| Initialize a git repo / open with VS Code? | 随意 |

生成后按 F5,会弹出 **Extension Development Host**(开发宿主窗口):按 `Ctrl+Shift+P` 执行 "Hello World" 命令,右下角弹提示 = 全链路已通。

### 2.2 项目结构速览(脚手架生成物)

```
vscode-workshop/
├─ package.json        ← 扩展清单:名字、publisher、命令、菜单、配置项全在这
├─ src/extension.ts    ← 扩展入口:activate() 里注册命令
├─ tsconfig.json
├─ .vscode/launch.json ← F5 配置(脚手架自带)
├─ .vscodeignore       ← 打包 .vsix 时排除的东西(node_modules、src 等,脚手架自带)
└─ esbuild.js          ← 打包脚本(选了 esbuild 才有)
```

改完代码:开一个终端跑 **npm run watch**(自动编译),再 F5 调试;断点直接打在 `extension.ts` 里。

### 2.3 清单里的关键字段(package.json)

```jsonc
{
  "name": "viora-workshop",
  "displayName": "Viora Workshop",
  "publisher": "你的发布者ID",              // 上架必需,先想好(全局唯一)
  "version": "0.1.0",
  "engines": { "vscode": "^1.85.0" },       // 别写太新的基线,用户量大
  "repository": { "type": "git", "url": "https://github.com/huyangpahuo/Viora" },
  "license": "SEE LICENSE",
  "activationEvents": [],                   // 有 contributes.commands 时会自动激活,留空即可
  "contributes": {
    "commands": [
      { "command": "viora.newPlugin", "title": "Viora 工坊: 新建风格插件", "category": "Viora" },
      { "command": "viora.pack",      "title": "Viora 工坊: 打包 zip",       "category": "Viora" },
      { "command": "viora.install",   "title": "Viora 工坊: 安装到本地 Viora", "category": "Viora" },
      { "command": "viora.registry",  "title": "Viora 工坊: 生成 registry 条目","category": "Viora" }
    ],
    "configuration": {
      "title": "Viora",
      "properties": {
        "viora.pluginsFolder": { "type": "string", "default": "",
          "description": "本机 Viora 的 plugins 文件夹绝对路径(安装命令用)" }
      }
    },
    "jsonValidation": [
      { "fileMatch": "plugin.json", "url": "./schemas/plugin.schema.json" }
    ]
  }
}
```

`repository` 和 `license` 一开始就填好——`vsce package` 会因为缺它们报错/警告。

## 3. 本地安装测试(.vsix)

调试没问题后,打一个安装包给自己/朋友试:

```bash
npm install -g @vscode/vsce
vsce package            # 生成 viora-workshop-0.1.0.vsix
```

VS Code 里:扩展视图右上角 `…` → **从 VSIX 安装…** → 选中刚才的文件;或命令行 `code --install-extension viora-workshop-0.1.0.vsix`。

## 4. 上架 VS Code Marketplace

一次性准备(约 10 分钟,做一次终身用):

1. **注册 Azure DevOps**:打开 https://dev.azure.com ,用微软账号登录,随便建一个组织(发布者验证要用);
2. **创建 PAT**(访问令牌):Azure DevOps 右上角头像 → **Personal access tokens** → New Token → Organization 选 *All accessible organizations* → Scopes 选 *Custom defined* → 勾 **Marketplace · Manage** → 生成后**立刻复制保存**(只显示一次;过期时间建议自定义,到期要重生成);
3. **创建发布者**:打开 https://marketplace.visualstudio.com/manage → Create publisher → 起一个全局唯一的 ID(这就是 package.json 里的 `publisher`,比如 `huyangpahuo`);
4. **发布者验证**:按页面提示完成验证(绑定你的 Azure DevOps 组织/微软账号)——不验证的发布者无法上架,这是微软防恶意扩展的硬要求。

之后每次发布只有两条命令:

```bash
vsce login huyangpahuo        # 粘贴刚才的 PAT,只需一次
vsce publish                  # 自动 package + 上传;发新版用 vsce publish patch / minor / major 自动抬版本号
```

也可以**手动上传**:本地 `vsce package` 出 .vsix,到 https://marketplace.visualstudio.com/manage → 你的发布者 → Upload。审核通常几分钟到几小时,通过后就能在市场搜到、`code --install-extension` 装到。

`vsce` 的常见拦路虎:

| 报错 | 处理 |
|---|---|
| `Make sure to edit the README.md` | 脚手架的 README 是模板,改成真实介绍即可 |
| `LICENSE, LICENSE.md or LICENSE.txt not found` | 把仓库根目录的 LICENSE 复制进扩展目录 |
| `repository field missing` | package.json 补 `repository.url` |
| 图标/预览图缺失(只是警告) | 建议放 128×128 PNG 作扩展图标(package.json 的 `icon` 字段) |

### 4.1 (可选)同步上架 Open VSX

VSCodium / Cursor 等非微软内核编辑器用的是 Open VSX 市场:https://open-vsx.org 注册 → 创建 access token → `npm i -g ovsx` → `ovsx publish -p <token>`。同一条命令也可以 `--packagePath` 直接传 .vsix。

## 5. 把实现交给 AI:任务书(直接整段贴给 AI)

> 在 D:\Viora 仓库里,按 AGENT.md 的约定实现插件工坊的 VS Code 扩展,目录 `vscode-workshop/`(TypeScript + esbuild,零运行时依赖:zip 用 PowerShell Compress-Archive 子进程,构建用 dotnet 子进程)。功能按 docs/06 §0 四条命令:① `viora.newPlugin`——向导收集 插件ID/显示名/作者/分类,按 docs/03 §1–§4 的结构生成完全自足的插件文件夹(csproj 引用 PluginSdk 且 `Private=false`、Plugin.cs 入口、示例 Stage、plugin.json);② `viora.pack`——对当前插件文件夹 dotnet build,产物 DLL + plugin.json 压成 `dist\<id>.zip`,并生成 `dist\registry-entry.json`;③ `viora.install`——把 zip 解压到设置项 `viora.pluginsFolder` 指向的 Viora plugins 文件夹;④ `viora.registry`——读 plugin.json 输出 registry 条目。另需 plugin.json 的 JSON Schema(jsonValidation)与插件 ID 规则诊断。验收:F5 后四条命令可用,打包产物可被 Viora 插件市场手动安装且风格正常出现在风格化页。
